# 體驗這件事｜我們一直只問了一半

**〔ONE〕AI Agent 正替顧客吸收搜尋與比較的步驟、壓縮顧客旅程，也改寫品牌被選擇的方式；從 UX 到 AX，能讓人與 AI 都信任的品牌才會勝出。**

## 深夜裡的核對

- 開場

〔M01〕晚上八點，理財顧問 Wendy 第四次把 AI Agent 剛產出的客戶資產配置報告，重新拉開 Excel 手動核對。這套 Agent 能在幾秒內彙整股票、基金與保單，上線三個月使用率卻遠低於預期。

〔M02〕問題出在它從不告訴顧問自己在做什麼：有沒有存取到最新資料、有沒有漏掉某個帳戶。它像一個悶著頭做事、從不回報進度的新人，動作再快，也沒人敢把重要的事交給它。

〔M03〕問題不在 Agent 的運算能力，而在它從沒被設計成「值得被信任的工作對象」。這就是 Agent Experience（AX，Agent 體驗）要談的。而它牽動的不只是像 Wendy 這樣的內部員工，還有每一個正在把決策交給 AI 的顧客。

## 體驗的主體，一直在擴張

- 體驗
- UX
- 真實的人類消費者
- 從 1990 年代起，UX 的主角一直是拿著手機、坐在電腦前的消費者
［圖表說明］UX（使用者體驗）關心人怎麼看懂畫面、完成操作。三十年來的方法論，都假設螢幕前是一個有情緒、會猶豫的人。

- TX
- 加上員工與決策者
- Gartner 的 Total Experience：CX、UX 與 EX 是相互牽連的生態系
［圖表說明］TX（整體體驗）把員工體驗也納進來：客服人員查資料很痛苦，電話那頭的顧客就不會有好體驗。但這一圈的主體仍然都是人。

- AX
- 加上 AI Agent
- 讓 Agent 在互動時也有順暢、可預測、可信賴的體驗
［圖表說明］AX（Agent 體驗）的「使用者」是軟體：它沒有視覺和情緒，卻有決策權。好體驗的標準從好看、直覺，換成穩定、可驗證、可追溯。

〔M04〕要理解 AX，得先回頭看 UX。在企業現場，討論的焦點永遠是那個拿著手機、坐在電腦前的消費者。從 1990 年代 Donald Norman 確立概念起，UX 從未被正面質疑過體驗的主體是誰：答案一直只有真實的人類消費者，而這個前提正在鬆動。

〔M05〕Gartner 2022 年提出的 Total Experience 框架，把顧客體驗 CX、使用者體驗 UX 與員工體驗 EX 看成相互牽連的生態系：員工查資料不順，顧客就難有好服務。Forrester 也印證，員工體驗好的企業，年均股票回報比同業高出 2.3% 至 3.8%。

〔M06〕但 TX 涵蓋的消費者、員工與決策者，仍然只有人這一種主體。2025 年，Netlify 執行長 Mathias Biilmann 提出 Agent Experience：當 AI Agent 成為使用產品的主體之一，它在互動時也需要順暢、可預測、可信賴的體驗。

- 延伸閱讀：Introducing AX
［延伸］Netlify 執行長 Mathias Biilmann 提出 Agent Experience（AX）的原始文章〈Introducing AX: Why Agent Experience Matters〉，也是本文 AX 一詞的出處。

- Mathias Biilmann 部落格

〔M07〕這股趨勢的規模，麥肯錫 2025 年的報告給出輪廓：88% 的受訪企業已在至少一項功能中定期使用 AI，但只有約三分之一開始規模化。也就是說，奠定標準的視窗期正在打開，現在做的設計決策，將決定未來十年的基準線。

## 顧客旅程正在被壓縮

〔M08〕過去二十年的顧客體驗建立在「人主動操作」上：有需求就搜尋、看到廣告就點擊、遇到問題就問客服。企業在顧客發出明確訊號後才回應，這是指令回應式體驗。

〔M09〕相對地，AI Agent 正把體驗推向代理協作式：它不只等待指令，而是理解目標、判斷情境、整理選項，在授權範圍內協助完成任務。Chatbot 解決的是回答問題的效率，Agent 改變的是任務本身如何被執行。

〔M10〕過去買旅遊產品要逐一比較航班、飯店、評論與保險；現在顧客只要說出預算、日期與偏好，Agent 就先整理出幾套方案，這就是顧客旅程壓縮。接觸點變少，每次被 Agent 選中反而更關鍵：當它只呈現三個選項而不是三十個，品牌如何被理解、排序與信任，就是新的競爭場。

## 從需求捕捉到需求預測

- 在顧客開口之前，就先理解他的狀態

〔M11〕過去企業等顧客主動搜尋、瀏覽、加購物車；AI 則讓企業能理解還沒說出口的訊號：反覆查看某類商品、購買週期接近、在流程中停留過久。但界線很細：同一種預測能力，企業可以拿來更早打擾顧客，也可以讓 Agent 懂得節制，知道何時該提醒、何時該沉默。

## AX 的六個核心信任模式

- AX 信任
- 意圖預覽
- 自主性調節
- 信心訊號
- 可解釋推理
- 行動稽核
- 升級路徑

〔M12〕UX 的訓練核心是同理心，但 Agent 沒有情緒，不會因為頁面好看而多停留；它會因為 API（系統之間交換資料的管道）回應不穩而中斷任務。Nielsen Norman Group 說得更直接：2026 年信任將是 AI 體驗最核心的設計問題，而且只會加劇。

- NN/g State of UX 2026
［延伸］Nielsen Norman Group 的年度報告〈State of UX 2026〉。文中「2026 年信任將是 AI 體驗最核心的設計問題」的判斷出自這份報告。

- Nielsen Norman Group

〔M13〕信任的建立有兩層。設計層是 AI 新創 Pixelmojo 歸納的六個 AX 信任模式：意圖預覽、自主性調節、信心訊號、可解釋推理、行動稽核與升級路徑；治理層則是企業要先回答 AI 知道我什麼、可以替我做什麼、做錯了誰負責，這決定顧客會不會放心把任務交出去。

〔M14〕低風險任務如查詢訂單可以高度自動化，高風險任務如金融交易、醫療建議則需要明確確認與人工支援。未來最成功的品牌，是最能讓顧客放心授權的品牌：顧客不授權，功能再多的 Agent 也動不了。

> 信任是 Agent Experience 能否運作的基礎設施。

## 實際案例：一個沒有升級路徑的退換貨 Agent

〔M15〕六個信任模式中的「升級路徑」有多重要，從一個電商客戶的退換貨 Agent 就看得出來：初版設計裡沒有清晰的升級路徑，遇到複雜案例時，Agent 不知道何時該停下來。

〔M16〕Agent 沒有停下來，先引用一般政策，發現不適用又改口引用瑕疵品條款，兩次回覆前後矛盾。

〔M17〕前後兩個答案讓顧客更困惑，他打出「所以到底可以退還是不可以」，語氣已經明顯不耐。

〔M18〕後來加入門檻：一旦涉及兩項以上政策交叉判斷，Agent 主動停下，請同仁協助確認，並把三個衝突點整理成摘要轉接。改版後，這類案例的顧客滿意度不再斷崖式下滑。

> Agent 的限制，是設計出來的，不是缺陷。

## 從 UX 跨越到 AX，有四堵牆必須翻越

〔M19〕AX 不是舊酒裝新瓶。Wendy 與退換貨的案例顯示：UX 的失敗發生在人看不懂畫面的那一刻，AX 的失敗則發生在 Agent 這類系統無法表達自身狀態的那一刻。因此過去衡量好體驗的好看、直覺，得換成穩定性、可驗證性、可追溯性。

- 第一堵牆
- 從設計介面，到設計工作條件

〔M20〕UX 設計師的產出一直是介面，但對 Agent 來說，介面幾乎不存在；它的工作條件是任務指令的精確度、資料存取的邊界與出錯時的回饋機制。麥肯錫也指出，早期成功案例的共同點不是挑了最聰明的模型，而是挑了最清晰的工作流程。

- 第二堵牆
- 從單一使用者，到多主體協同

〔M21〕多主體協同不只發生在多個 Agent 之間，也在顧客端與員工端之間：員工若得在多個系統間查資料、複製貼上，顧客就很難得到即時一致的服務。前台 Agent 再聰明，如果後台資料分散、流程斷裂、員工無法接手，顧客感受到的仍是不連貫的體驗。

- 第三堵牆
- 從單次會話，到持續關係

〔M22〕UX 優化單次會話，AX 優化持續的關係：Agent 把今天學到的記住，明天讓自己更有用。因此設計師必須思考記憶架構：Agent 該記住什麼、記多久，什麼情況下記憶反而帶來偏誤而需要被重置。

- 第四堵牆
- 從以人為中心，到以信任為中心

〔M23〕對人類，信任靠一致的視覺語言建立；對 Agent，信任靠穩定的 API 回應與可驗證的資料格式。而回到人這一端，世界經濟論壇指出：要讓人信任一套 AI 系統的作為，得先讓人看懂它知道什麼、被允許做什麼、實際做了什麼。

- 世界經濟論壇：為 AI Agent 設計信任
［延伸］世界經濟論壇 2026 年 2 月的文章〈How to Design for Trust in the Age of AI Agents〉，是原文在第四堵牆「以信任為中心」附註的參考來源，延伸談 AI Agent 時代怎麼設計信任。
