# 首頁「開場之後」設計腦力激盪紀錄

日期：2026-11-19　範圍：首頁開場（雙像匯聚）之後、帶讀者進到 22 篇文章的那一段
既有三案（星圖、書櫃、觀點跑馬牆）已有可操作原型（`docs/design-review/home-concepts.html`），本次列為**備案**，重新發想。

## 與會角色

| 角色 | 職責 | 限制 |
|---|---|---|
| 設計總監（主導設計師） | 提案、回應意見、修訂 | 不能自己核准 |
| 藝術總監（挑戰者） | 假設這案會失敗，找出為什麼 | 不提新功能、不重新設計 |
| 前端與無障礙負責人（約束守護者） | 效能、手機、減少動態、無 JS、維護成本 | 不爭論產品目標 |
| 使用者研究員（使用者代言人） | 認知負荷、第一眼看不看得懂、點擊目標 | 不改架構 |
| 執行創意總監（仲裁者） | 接受或駁回意見、宣布結論 | 不新增需求 |

## 理解鎖定（大家先同意的前提）

1. **全站最強的資產是開場「兩張臉匯聚」**：鉛筆短線組成的人臉、像素方塊組成的 AI 臉，捲動時匯聚、相望。觀眾記得的是它。
2. 書的核心命題是「品牌離 AI 越近，會離人越遠嗎？」——**距離**是整本書的關鍵詞。
3. 四章：序章（2 篇）、人 People（9）、模型 Model（5）、行動 A.I（6）。
4. 評審第一次打開時**已讀篇數是 0**。任何靠「讀越多越好看」的設計，第一眼必須在 0 篇時就好看。
5. 這一段要同時做三件事：讓人一眼看懂整本的結構（導引）、讓人想點進一篇（吸引）、讓人想讀更多並分享（遊戲化）。
6. 限制：靜態站、CSP 不允許行內腳本、要支援減少動態與無 JS、手機是主要裝置之一。

## 第一階段：設計總監提出六個新方向

既有三案的共同弱點：**它們都跟開場沒有關係**。星空、書櫃、跑馬燈各自成立，但讀者捲過兩張臉之後，視覺語言突然換掉，記憶點斷了。新方向的原則是「延續那兩張臉」。

| # | 名稱 | 一句話 |
|---|---|---|
| N1 | **替這張臉上色** | 開場那兩張臉匯聚完成後不消失，變成全書地圖：臉上分成 22 個區塊，一篇一塊。讀一篇，那一塊從鉛筆灰變成章節色。 |
| N2 | 人—AI 光譜尺 | 一把橫向的尺，左端鉛筆、右端像素，22 篇依論點靠近「人」或「AI」排在尺上。 |
| N3 | 編輯部目錄跨頁 | 雜誌等級的字體目錄：超大頁碼、襯線標題、作者、一句話；滑過時標題從鉛筆筆觸「像素化」。讀過的條目被鉛筆打勾、劃線。 |
| N4 | 22 個問題的對話 | 每篇只留結尾帶走的問題；問題用 AI 打字的方式出現，讀過的篇章換成手寫字回應。 |
| N5 | 牛皮紙剪報桌 | 刊物原有的小插圖剪下來、膠帶貼在牛皮紙桌上，一張剪報一篇。 |
| N6 | 一條鉛筆線 | 一條手繪線貫穿整頁，經過 22 站，到 AI 那章線變成像素；像手繪的捷運圖。 |

設計總監初選：**N1 為主、N3 為輔、N6 備選**。

## 第二階段：審查

### 藝術總監（挑戰者）

| 對象 | 意見 |
|---|---|
| N1-1 | 臉被切成 22 塊、還沒讀的是灰的或缺的，看起來像「裂開的臉」，等於說 AI 讓人支離破碎，跟書的立場相反。 |
| N1-2 | 開場剛把兩張臉拼完整，下一段又把它拆散，是在否定開場的高潮。 |
| N1-3 | 大部分讀者只讀 1～2 篇，臉只會亮 5～10%，看起來像「什麼都沒完成」，反而打擊人。 |
| N1-4 | 在臉上點區塊是沒人學過的操作，讀者不會知道那可以點。 |
| N3 | 很漂亮，但單獨用就是「又一個雜誌風網站」，不會讓評審眼睛一亮。 |
| N2 | 把作者的論點排在「靠人／靠 AI」的尺上是編輯判斷，作者可能不同意，也沒有原文依據。 |
| N4、N6 | 打字機效果和捷運圖都用爛了；N6 還要捲很長才看完 22 站，增加阻力。 |
| N5 | 和書櫃同一類（擬物），只是換了道具。 |

### 前端與無障礙負責人（約束守護者）

1. N1 必須**沿用開場同一個 canvas 與粒子**，不能再起第二套粒子系統；手機粒子數要設上限，捲動中維持每格 16ms 以內。
2. 22 個區塊的切法要在建置時算好、固定不變，不能每次載入隨機。
3. 減少動態：直接給靜態 SVG（臉＋區塊色）。無 JS：只顯示文字目錄。
4. 分享卡沿用現有分享卡流程（canvas 輸出圖），臉的上色狀態可以直接畫進去，不另外開服務。
5. N3 成本約半天；N1 約 2～2.5 天。

### 使用者研究員（使用者代言人）

1. 讀者三秒內要知道「這裡可以做什麼」。如果標題只出現在滑鼠移上去的提示框裡，等於把導引藏起來。
2. 手機上 22 個臉部區塊，有一半會小於 40px，點不準。
3. 評審第一次來是 0 篇。N1 在 0 篇時如果是灰的、破的，第一印象就輸了。
4. 「上色」要讓讀者明白是因為「我讀了」才亮，不然會以為是隨機動畫。

## 設計總監的修訂

針對上面的意見，N1 改成下面這樣（N3 併入成為它的另一半）：

**「22 塊顏色，拼回人的溫度」**

- **臉永遠是完整的**（回應 N1-1、N1-2、研究員 3）：開場匯聚完成的兩張臉留在畫面上，不拆、不缺。0 篇時是完整的鉛筆灰與像素灰，仍然是開場那個好看的畫面。
- **讀過的區塊上色**（回應 N1-3）：讀一篇，臉上對應的區塊從灰變成章節色，像素方塊和鉛筆線在那一塊微微發光。標語「讀越多，這張臉越有溫度」。讀 1 篇就看得見一塊亮起，不是「完成度 5%」的進度條語感。
- **區塊有意義**：人這章 9 篇在鉛筆人臉上，行動這章 6 篇在 AI 臉上，模型這章 5 篇在**兩張臉之間的空隙**（這本書講的「距離」），序章 2 篇在兩隻眼睛。看一眼就懂四章的關係。
- **主要導引是旁邊的字體目錄（N3）**（回應 N1-4、研究員 1、2）：桌機上臉固定在左側，右側是編輯部風格的 22 篇目錄（大頁碼、標題、作者、一句話），全部直接看得到。滑過某一列，臉上那一塊亮起；滑過臉上某一塊，目錄那一列反白。點臉是加分，不是唯一入口。手機上臉縮成頂部一條小圖固定住，下面是目錄，只靠點目錄列。
- **上色當下有回饋**（回應研究員 4）：讀完一篇回到首頁，那一塊用 0.8 秒從灰「染」開，旁邊浮出「你剛讀完〈信任〉，替這張臉添了一塊色」。
- **分享**：分享卡直接是「你的那張臉」，每位讀者上色的位置不同，天然有個人化與收集感。
- **主線**：點主線時，該主線的幾塊同時亮起，目錄只留那幾列。

| AD N5 同類 | 接受 | 併入書櫃備案，不另做。 |

**結論：APPROVED（核准進入原型）**，附條件：

1. 先做可操作原型，放進現有提案頁當第四案，和書櫃並排比較；確認後才動正式首頁。
2. 原型必須在 **0 篇、3 篇、22 篇** 三種狀態各截圖，0 篇時要好看。
3. 手機 390px 上臉部小圖與目錄的版面要先驗證。
4. 區塊切法建置時固定，沿用開場的 canvas。

## 備案排序

1. **新主案：替這張臉上色**（N1＋N3）
2. 書櫃（已有原型，擬物、溫度最高）
3. 星圖（已有原型）
4. 一條鉛筆線（N6，未做原型）
5. 觀點跑馬牆（已有原型）

淘汰：N2 人—AI 光譜尺、N4 問題對話、N5 剪報桌（併入書櫃）。
