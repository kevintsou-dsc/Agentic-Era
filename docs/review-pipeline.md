# 故事審稿流程：Jev 初評 → 改寫 → 人工校閱

> 2026-10-25。回應使用者回饋第 4 點：「不想完全由人工審核，先透過 Jev 判斷初評 → 調整為更好的寫法 → 最後再人工校閱；需評估成本、確定有效果再套用全站，效果不好就採替代方案。」
> 結論：**試驗通過，採用。** 數據見 §2，全站流程見 §3。

## 1. 為什麼用 Jev，以及它不做什麼
- Jev（TypeSafe）是「裁判」模型：只回答 Noul（是／否機率）、Score（分數）、Choice（選項）。它不寫字，所以**改寫由 Claude 完成，Jev 只負責判斷改寫前後的品質**，兩者不互相評分自己的產出。
- 每個審查單位各送一次請求（一份 state 只放一段主文與它的原文），避免批次塞多筆造成的位置效應。

## 2. 有效性試驗（先驗證，再套用）

### 2.1 設計
- **原句**：4 篇已寫好的故事（a08、a10、a11、a13），共 66 個單位（主文段落與圖表細節）。用來量**誤判率**。
- **突變句**：對每個原句注入 5 種常見錯誤，共 238 句。用來量**抓錯率**。
  - M1 改數字（例如 79% → 161%）
  - M2 誇大或過度概括（「可能」→「必然」，或加上「適用於所有品牌」）
  - M3 換名字（CeraVe → Olay、金曲獎 → 金馬獎）
  - M4 捏造因果（加上「並因此讓營收成長三倍」）
  - M5 半句（截斷後以冒號結尾，也就是使用者指出的「主文有缺」）
- **故事層級**：原故事、打亂段落順序（測連貫性）、只留一半段落（測完整性）。
- **對照組**：不用模型的規則比對（主文中的數字與英文專有名詞必須出現在原文）。
- 腳本：`scripts/review/jev_pilot.py`、`analyze_pilot.py`；原始結果：`content/review/jev-pilot.json`。

### 2.2 結果（jev-latest，2026-10-25）
| 項目 | Jev | 規則比對 |
|---|---|---|
| M1 改數字 | **100%** | 100% |
| M2 誇大 | **97%** | 8% |
| M3 換名字 | **89%** | 22% |
| M4 捏造因果 | **100%** | 8% |
| M5 半句（complete < 0.3） | **94%** | 6% |
| 原句被標記 | 16.7%（11／66） | 7.6% |
| 故事連貫性：原文 → 打亂 | 2.6 → 1.2（滿分 3） | — |
| 故事涵蓋度：原文 → 半篇 | 2.9 → 2.1 | — |
| 成本／時間 | **US$0.05**（1,240 題）／**8 秒** | 0 |

**關鍵發現**：被標記的 11 句「原句」逐一人工檢查後，**多數不是誤判，而是真的問題**：主文寫的內容超出它所引用的那段原文。
- 18%、79% 這兩個數字來自圖表，但引用的是文字段落。
- 「《魔女宅急便》音樂劇……」的前半句沒有出處。
- 「這是 2004 年的觀察值」這句話原文根本沒有。

使用者第 1 點要求「每段文字附上原文出處，點擊就能看原文」，這類問題正是要抓出來的。所以實際誤判率遠低於 16.7%。

**判定**：抓錯率遠高於預設標準（≥ 80%），成本可以忽略，**採用**。規則比對只能抓數字，不能取代 Jev，但它免費，保留為第 0 輪。

## 3. 全站流程

```
撰寫（Claude）
  └→ 第 0 輪：npm run verify      逐字比對＋作者職稱＋主文 lint（硬規則，必須全過）
  └→ 第 1 輪：Jev 初評            jev_review.py → docs/review/roundN.md（依風險排序的待修清單）
  └→ 改寫（Claude）               只改被標記的段落：補上真正支撐這句話的原文，或把句子改回原文的語氣
  └→ 第 2、3 輪：Jev 複評         最多三輪；仍未通過的段落轉人工，並在報告中註明
  └→ status: 'judged'
  └→ 人工校閱（使用者）           讀網站上的故事＋報告中的轉人工項目 → status: 'reviewed'
```

**門檻**（`scripts/review/jev_review.py`）

| 指標 | 門檻 | 說明 |
|---|---|---|
| faithful | < 0.30 標記 | 主文超出所引原文 |
| overclaim | > 0.80 標記 | 語氣或範圍比原文強 |
| complete | < 0.30 提示 | 可能是半句；硬規則由 lint 負責 |
| coverage | < 2.5 標記 | 故事層級，滿分 3 |
| coherence | < 2.2 標記 | 故事層級，滿分 3 |

**全站成本估算**：22 篇約 400 個單位 × 4 題，加上 22 篇 × 2 題，每輪約 1,650 題，約 US$0.06。三輪合計不到 US$0.2，時間每輪約 10 秒。

## 4. 這次 4 篇的實際成果

| 輪次 | 標記數（66 個單位） | 故事層級 |
|---|---|---|
| 第 1 輪 | 20 | a11 連貫性 2.24 |
| 改寫後 第 2 輪 | 4 | a11 連貫性 2.19（未達 2.2） |
| 改寫後 第 3 輪 | 1 | a11 連貫性 **2.45** ✓ |
| a11 再兩輪 | 1（轉人工） | a11 連貫性 **2.50** ✓ |

Jev 抓到、且人工確認屬實的問題類型：
1. **出處不足**（14 項）：數字來自圖表、名稱出現在別頁、整句沒有原文依據。改法是補上真正支撐的那段原文。
2. **語氣被改強**：原文說「反而**可能**變少」，主文寫成「反而變少」。
3. **用字替換**：原文說「再創作」，主文寫成「二創」。
4. **半句**：圖表細節只寫「直播、節慶、復刻……」，沒有主詞。改成完整句子。
5. **故事銜接**：〈從金曲獎到甄嬛傳〉的段落之間缺少轉折。補上「如果金曲獎代表的是受眾橋接……」之後，連貫性從 2.19 提高到 2.50。

**轉人工的項目**（第 5 輪 faithful 0.27，緊貼門檻，前後幾輪在門檻上下浮動）
- a11 五階段第二段：「第三步是讓人重新使用這段記憶……第四步是讓熟悉的東西，成為通往新內容的入口。」原文的行動表沒有編號，「第三步、第四步」是策展者的整理。請人工判斷是否保留。

## 5. 替代方案（若之後 Jev 表現變差）
- **A**：規則比對（第 0 輪）加上 Claude 依 story-guide §4 清單自評。成本是 Claude token，抓錯率未驗證，需要先用同一套突變資料重測。
- **B**：只靠人工，但依規則比對的結果排序，先看有數字與專有名詞的段落。
- 觸發條件：Jev 換版後重跑 `jev_pilot.py`，抓錯率平均低於 80%，或原句標記率高於 30% 且多數是誤判。

## 6. 已知限制
- Jev 的分數有雜訊：同一句在門檻附近（0.25–0.35）會在不同次執行中翻轉。所以設最多三輪，之後轉人工，不追求 100% 通過。
- 突變是程式產生的「典型錯誤」，真實錯誤可能更隱晦（例如因果方向反了）。人工校閱仍不可省。
- 金鑰只從 jev-test 專案的 `.env.local` 讀取，不進本 repo；審查用的文字（刊物內容）會送到 TypeSafe API。
