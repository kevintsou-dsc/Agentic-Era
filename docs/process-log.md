# 製作歷程（Process Log）

> 每筆記錄：日期｜做了什麼｜用了什麼提示或工具｜AI 給了什麼｜人做了什麼判斷或修改｜為什麼。這份文件會精選成繳交用的「製作歷程」。

## 2026-10-23｜第一階段規劃
- **做了什麼**：閱讀比賽頁與四個範例網站；確認 OneDrive 素材可讀（197 個檔案，PDF 文字可抽取）；用 multi-agent-brainstorming 做結構化設計審查。
- **流程**：主導設計師提出 v0 → 懷疑者（13 條）→ 約束守護者（16 條）→ 用戶倡導者（12 條）→ 仲裁者裁決 REVISE → 修訂後寫成 PRD v1.0。紀錄在 `docs/design-review/`。
- **AI 出錯、被審查抓到的例子**：v0 舉了「GEO 篇 vs 社群篇是對立觀點」的例子，懷疑者對照摘要後指出兩篇其實方向一致，是硬造的對立。修正方式：禁止標示對立，關係只分呼應／補充／不同側重，而且每條關係都要附兩邊原文並經人工核可。
- **查證發現**：xlsx、PDF 目錄、單篇檔名，三處標題寫法不一致（例如第 20 篇有三種寫法）；章節素材圖是假字的版型示意，不能當內容來源；版權頁含公關 Email，需要排除；上層工作區資料夾放有其他專案的機密設定檔，因此 git root 鎖在專案資料夾，並採白名單式 .gitignore。
- **待人判斷**：PRD §12 的 K1–K11。

## 2026-10-24（晚）｜選定結構 C，從 POC 變成正式架構
- **人的判斷**：比較兩個 POC 後選 C（全書故事＋單篇 90 秒＋原文）。PRD 改為 v2.0。
- **架構重寫**：POC 的圖表是一篇一個元件，22 篇做不完 → 改成資料驅動。
  - 6 種通用圖形：bars、hbars、cycle、layers、matrix、list，搭配 4 種場景（graphic、quote、bignum、statement）。
  - 每篇故事是一個 `src/data/stories/aNN.ts` 資料檔，不用再寫元件。
  - 圖形狀態統一由 CSS 變數 `--on`、`--focus` 驅動，元件不寫任何捲動程式碼。
- **單一事實來源**：22 篇的標題、作者、職稱、頁碼、主線集中在 `content/articles.json`。
- **新閘門 1：作者與職稱比對**（`verify-meta.mjs`），把每位作者的姓名、英文名、職稱拿去比對內頁。
  - 第一次執行 100 項有 6 項失敗。原因是 AI 把共同作者的公司名稱重複加在每個人的職稱前面，但內頁只印一次 → 改用 `org` 欄位。
  - 查證過程也發現 xlsx 與內頁的職稱不一致，依 K4 以內頁為準。例如紀緻謙內頁是「電通創意專業服務執行長」，強義明內頁是「凱絡媒體數位運營總統籌」。
- **新閘門 2：斷鏈檢查**（`check-links.mjs`），建置後掃 dist 的所有站內連結與錨點：306/306 有效。
- **引文閘門收緊**：原本允許引文落在「宣告頁或下一頁」，會讓整句其實在下一頁的引文用錯的頁碼過關 → 改成只接受在宣告頁、或確實跨頁的引文。
- **CSP**：Astro 預設把小腳本與 CSS 內嵌進 HTML，會違反 `script-src 'self'` → 設定 `inlineStylesheets: 'never'`、`assetsInlineLimit: 0`。結果全站 0 個內嵌 script／style，JS 合計 1.1 KB（gzip）。唯一的例外是 `style-src-attr 'unsafe-inline'`，用來讓圖表以 style 屬性傳入長條高度，風險低，會寫進資安自評。
- **審稿流程**：故事檔有 `reviewed` 欄位，全文有校正清單。開發期間草稿也上線，但頁面標示「草稿：待人工審定」「未校正」。繳交前由 `npm run verify:release` 要求 22 篇全部審定。
- **首次上線（2026-10-24）**：使用者以 Cloudflare Workers（靜態資產）部署於 `agentic-era.kevin-tsou.workers.dev`，推送 main 即自動建置。
  - 線上檢查：7 個路徑狀態碼正確，404 回傳自訂頁，`/dev/gallery/` 正式站不存在。`_headers` 的 8 個安全標頭全部生效；`/_astro/*` 為一年 immutable 快取；瀏覽器主控台沒有任何 CSP 違規。
  - 線上發現的問題：在很矮的視窗（約 766×328，相當於手機橫放），文字卡片蓋住圖表 → 高度 ≤ 560px 時改成圖在上、文字在下，圖形直接顯示最終狀態。
  - 已知限制：`workers.dev` 網域無法設定 HTTP 自動轉 HTTPS。已有 HSTS 標頭，瀏覽器第一次用 HTTPS 造訪後會強制 HTTPS；這點寫進資安自評。
- **驗證方式的轉折（2026-10-24）**：瀏覽器面板被隱藏時，頁面不會重繪，截圖與捲動都會逾時 → 加了一個只在開發模式存在的 `/dev/gallery/`，用 headless Edge 截圖，一次檢查所有圖形的最終狀態。重點是 Cloudflare Pages 能設定 HTTP 安全標頭，讓資安自評可以附上第三方檢測結果；GitHub Pages 做不到。

## 2026-10-25｜使用者回饋五點：出處視窗、圖表細節、主文連貫、Jev 審稿、橫向捲動
- **人的判斷（使用者回饋）**：
  1. 每段文字都要能點開原文。
  2. 圖表要能 hover／點擊看更多細節。
  3. 主文有缺，讀起來不完整，先重新梳理故事線。
  4. 審稿不要全靠人工：先用 Jev 初評，再改寫，最後人工校閱；要先驗證效果與成本，不好就換方案。
  5. 加入橫向捲動，避免讀者疲乏。
- **1 書頁視窗**：每段主文後面加「紙本 p.xx」按鈕，開啟原生 `<dialog>`，樣式做成書頁。建置時在全文中找到引文，連同前後文一起顯示並高亮。引文與原文的空白、全形半形不同，所以逐字元正規化並保留原始位置，才能把高亮準確對回原文。視窗內附「讀這一頁的原文」連結，連到原文頁的頁碼錨點。
- **2 圖表細節**：長條、橫條、循環節點、分層、清單項目都可以加 `detail`。桌面版 hover 會顯示提示；點「ⓘ 細節」則開書頁視窗，附上原文。
- **3 主文與旁資訊分離**：寫了 `docs/story-guide.md`，內容是兩條軌道（主文講完整論點，旁資訊補證據與細節）、六段弧線，以及硬規則。新增 `lint-stories.mjs`：每段主文要以句末標點結束、不能以冒號結尾、要有出處，長度有上下限。第一次執行就抓到 a08 一段「作者的結論是：」的半句。另外寫了 `docs/story-outlines.md`，規劃 22 篇的故事線；4 篇已完成的故事也依新規範全部重寫。
- **5 橫向捲動**：`HScroll` 場景讓讀者往下捲時，畫面橫向移動；矮視窗與「減少動態」時退回原生左右滑動。第一版在寬螢幕上 4 格幾乎全部放得下，移動感很弱 → 加寬每一格，讓畫面只露出約 2.3 格。
- **4 Jev 審稿**：先做有效性試驗再決定是否採用，詳見 `docs/review-pipeline.md`。
  - 對 66 個原句注入 5 種錯誤，Jev 抓錯率 89–100%，成本 US$0.05、8 秒。
  - 被標記的「原句」逐一人工檢查後，多數是真的出處不足。
  - 正式跑了 3 輪（a11 多兩輪）：標記從 20 → 4 → 1，a11 的連貫性從 2.19 提高到 2.50。
  - 最後 1 項分數緊貼門檻，依規則轉人工。4 篇狀態改為 `judged`（AI 初評通過，待人工校閱）。
- **AI 的錯被 AI 抓到**：Jev 抓到 Claude 改寫時把原文的「反而可能變少」寫成「反而變少」，也把「再創作」換成「二創」。
- **建置閘門又抓到的問題**：原文檔在 Windows 是 CRLF 換行，原文頁的頁碼錨點全部沒有產生。斷鏈檢查一次報出 89 個錨點錯誤 → 讀檔時統一換行。

### 2026-10-25｜無圖卡片直接顯示細節；案例圖片畫質修正
- 回饋：橫向捲動卡片沒有圖片時下半部空白，細節要按按鈕開彈窗；部分案例圖片很糊。
- 卡片：沒有圖片的格把細節（引文、連結）直接攤在卡片上，超過 90 字改為卡片內下拉展開。細節內容抽成 `MoreBody.astro`，彈窗與卡片共用。
- 畫質原因分析：
  1. 抽圖腳本固定以 2.5 倍（約 180dpi）裁切渲染，PDF 內嵌圖其實多為 200–400dpi。例如《憤怒鳥》內嵌 1248px，舊輸出只有 563px。
  2. 部分原始素材本身就小（InDesign Links 資料夾內多為 400–600px 截圖），卡片寬約 34rem，在高解析螢幕上被放大 2 倍以上。
  3. 橫幅海報（《魔女宅急便》4.3:1）在卡片中用 cover 裁切，只取中間一小塊再放大。
  4. PDF 的 JPEG 再壓一次 WebP（品質 78），雙重失真。
- 修正：改依內嵌原始像素決定渲染倍率（2.5–6 倍）、最長邊 1600、品質 86；37 張圖解析度提升（多數 1.5–2.2 倍），總量 1.5MB → 2.8MB。橫幅圖改為完整顯示；一般圖片不放大超過原始寬度。
- 不採用直接引用外部圖片網址：違反 CSP（default-src 'self'）、外連會失效，也有第三方追蹤與授權問題。規則寫入 story-guide §5.2。
