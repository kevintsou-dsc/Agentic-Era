# 製作歷程（Process Log）

> 每筆記錄：日期｜做了什麼｜用了什麼提示或工具｜AI 給了什麼｜人做了什麼判斷或修改｜為什麼。這份文件會精選成繳交用的「製作歷程」。

## 2026-10-23｜第一階段規劃
- **做了什麼**：閱讀比賽頁與四個範例網站；確認 OneDrive 素材可讀（197 個檔案，PDF 文字可抽取）；用 multi-agent-brainstorming 做結構化設計審查。
- **流程**：主導設計師提出 v0 → 懷疑者（13 條）→ 約束守護者（16 條）→ 用戶倡導者（12 條）→ 仲裁者裁決 REVISE → 修訂後寫成 PRD v1.0。紀錄在 `docs/design-review/`。
- **AI 出錯、被審查抓到的例子**：v0 舉了「GEO 篇 vs 社群篇是對立觀點」的例子，懷疑者對照摘要後指出兩篇其實方向一致，是硬造的對立。修正方式：禁止標示對立，關係只分呼應／補充／不同側重，而且每條關係都要附兩邊原文並經人工核可。
- **查證發現**：xlsx、PDF 目錄、單篇檔名，三處標題寫法不一致（例如第 20 篇有三種寫法）；章節素材圖是假字的版型示意，不能當內容來源；版權頁含公關 Email，需要排除；上層工作區資料夾放有其他專案的機密設定檔，因此 git root 鎖在專案資料夾，並採白名單式 .gitignore。
- **待人判斷**：PRD §12 的 K1–K11。

## 2026-10-24｜使用者定案與創意方向調整、內容盤點
- **人的判斷**：K2、K4 照建議；K6 個人參賽；K7 所有素材可用；K9 公開 repo。**創意方向由人改寫**：把 AI 提的「決策室／圓桌」改為「像看故事一樣往下捲動就讀完」，優先順序 UI/UX → 資訊視覺化 → 炫技。使用者要求先把內容與數據讀懂，再決定形式。
- **做了什麼**：寫 `scripts/extract/extract_fulltext.py`（PyMuPDF，依跨頁左右頁與兩欄座標排序）抽出 22 篇全文；寫 `scan_figures.py` 掃出 126 個數據句；把 92 個跨頁做成縮圖逐頁檢視，並放大確認圖表數字。
- **抽取過程的三次修正**：
  1. 第一版每一行都變成一段，首字放大被誤判成標題 → 改成依行距合併段落，單字標題併入下一段。
  2. 頁眉「:People45」「97 :Model」混進內文 → 補上兩種頁眉格式的過濾規則。
  3. **檔名編號與印刷順序不一致**：用頁眉頁碼交叉核對，發現 2-14 其實是 p.136、2-15 才是 p.128，AI 原本照檔名排序的對應是錯的 → 改為以頁眉頁碼為準。
- **重要發現**：全書約 14.3 萬字、讀完約 5 小時 15 分，支持「濃縮」的方向。真正的圖表只有 6 張，大部分可視覺化素材是約 25 個框架。其中第 16 篇的雷達圖原本就標示「示意圖」，不能當成真實數據呈現。詳見 `docs/content-study/content-map.md`。
- **部署平台（K3）說明**：見 PRD §9.1。

## 2026-10-24（下午）｜A／C 兩種故事結構的 POC
- **人的判斷**：使用者把候選結構縮小到 A（一條主線長故事）與 C（全書故事＋單篇 90 秒），要求先做小範圍 POC 比較。
- **範圍**：同一批素材做兩次。素材是「從注意力到記憶」這條線，包含何華軒、徐莉媛、吳宗霖與陳炯文、吳宗霖四篇。
  - A：`/poc-a`，4 篇串成約 3 分鐘的故事。
  - C：`/poc-c`（22 個點代表全書，捲動依序點亮四條主線）與 `/poc-c/a10`（單篇 90 秒）。
- **技術**：Astro 5 靜態輸出，沒有任何前端框架；捲動引擎約 90 行 TypeScript；圖表全是手寫 SVG／CSS，數字取自 PDF 向量圖。
- **逐字比對閘門第一次上線**：`scripts/verify/verify-quotes.mjs` 把 `src/data/*.ts` 的每則引文和數字拿去跟全文比對，並檢查頁碼。第一次執行就抓到 AI 憑印象寫錯的頁碼：〈重建 SOV〉那句「單次銷售是 Sales…」寫成 p.117，實際在 p.119。`npm run build` 現在會先跑這道檢查。
- **試作中修掉的問題**：
  1. Doom Loop 箭頭跟著線寬放大 → 改成固定尺寸。
  2. 長條數值標籤固定在頂端，沒有貼著長條 → 改成 flex 由下往上排。
  3. 「+46%」與 3.37 重疊 → 移到標題旁。
  4. 重新整理後、或停在最後一步之後，圖表變空白（IntersectionObserver 只在跨過中線時觸發）→ 改成依捲動位置直接算出目前步驟，快速捲動也不會漏步。
  5. 手機上矩陣的直書軸標難讀 → 窄螢幕改成橫書。

## 2026-10-24（晚）｜選定結構 C，從 POC 變成正式架構
- **人的判斷**：比較兩個 POC 後選 C（全書故事＋單篇 90 秒＋原文）。PRD 改為 v2.0。
- **架構重寫**：POC 的圖表是一篇一個元件，22 篇做不完 → 改成資料驅動。
  - 6 種通用圖形：bars、hbars、cycle、layers、matrix、list，搭配 4 種場景（graphic、quote、bignum、statement）。
  - 每篇故事是一個 `src/data/stories/aNN.ts` 資料檔，不用再寫元件。
  - 圖形狀態統一由 CSS 變數 `--on`、`--focus` 驅動，元件不寫任何捲動程式碼。
- **單一事實來源**：22 篇的標題、作者、職稱、頁碼、主線集中在 `content/articles.json`。
- **新閘門 1：作者與職稱比對**（`verify-meta.mjs`），把每位作者的姓名、英文名、職稱拿去比對內頁。
  - 第一次執行 100 項有 6 項失敗。原因是 AI 把共同作者的公司名稱重複加在每個人的職稱前面，但內頁只印一次 → 改用 `org` 欄位。
  - 查證過程也發現 xlsx 與內頁的職稱不一致，依 K4 以內頁為準。例如紀緻謙內頁是「電通創意專業服務執行長」，強義明內頁是「凱絡媒體數位運營總統籌」。
- **新閘門 2：斷鏈檢查**（`check-links.mjs`），建置後掃 dist 的所有站內連結與錨點：306/306 有效。
- **引文閘門收緊**：原本允許引文落在「宣告頁或下一頁」，會讓整句其實在下一頁的引文用錯的頁碼過關 → 改成只接受在宣告頁、或確實跨頁的引文。
- **CSP**：Astro 預設把小腳本與 CSS 內嵌進 HTML，會違反 `script-src 'self'` → 設定 `inlineStylesheets: 'never'`、`assetsInlineLimit: 0`。結果全站 0 個內嵌 script／style，JS 合計 1.1 KB（gzip）。唯一的例外是 `style-src-attr 'unsafe-inline'`，用來讓圖表以 style 屬性傳入長條高度，風險低，會寫進資安自評。
- **審稿流程**：故事檔有 `reviewed` 欄位，全文有校正清單。開發期間草稿也上線，但頁面標示「草稿：待人工審定」「未校正」。繳交前由 `npm run verify:release` 要求 22 篇全部審定。
- **驗證方式的轉折**：瀏覽器面板被隱藏時，頁面不會重繪，截圖與捲動都會逾時 → 加了一個只在開發模式存在的 `/dev/gallery/`，用 headless Edge 截圖，一次檢查所有圖形的最終狀態。重點是 Cloudflare Pages 能設定 HTTP 安全標頭，讓資安自評可以附上第三方檢測結果；GitHub Pages 做不到。
