## 二、依風險分三級

1. **高風險：改寫原文**（主文、一句話、帶走的問題、圖表標題與標籤）。讀者會當成作者的意思，最怕的是說得比原文強、漏掉條件、把例子講成通則，或沒照新規則處理作者稱呼。
2. **中風險：策展補充**（說明框、延伸摘要、外部連結說明、地基「缺了這塊」、文氏圖說明、對照欄標題）。原文沒有，要確認是一般公認的知識、有標示為補充、沒有替作者下結論。這一級大多沒經過 Jev。
3. **低風險：機械性**（原文引言、圖說出處）。逐字的部分已自動檢查；圖說只需統一格式。

## 三、檢核表（每一則都問這幾題）

- **忠實**：主張在 src 裡找得到；沒有加上原文沒說的「最」「一定」「所有」；數字、單位、年份與原文相同。
- **完整**：沒有斷章取義的半句；有條件的說法保留條件（例如「在 B2B 情境」）。
- **稱呼**：不直呼作者中文名；親身經歷需要主詞時用英文名（Jennifer、Cynthia、Jeremy 等）；中文名一律加完整職稱；不用「他／她」。
- **好讀**：一句一個重點；單句不超過約 60 字；避免連續三個以上的專有名詞；相鄰段落有銜接。
- **一致**：同一個概念全站用同一個詞（建術語表：AI Agent 已定案；其他如衡斷力、CEPs 待整理）；全形標點；數字與單位格式一致。
- **策展補充**：說明框開頭說「這是什麼」，再說「為什麼重要」；只寫一般公認的知識；不替作者延伸結論。

## 四、流程（每篇）

1. **自動檢查**（我）：`npm run story:check` 全過。新增三項風格 lint：
   - 單句超過 60 字（提示）
   - 半形標點混用（擋下）
   - 術語不一致（依術語表，擋下）
2. **Jev 初評擴大範圍**（我）：
   - 目前 Jev 只評主文。
   - 擴充 `scripts/review/jev_review.py`，把說明框、延伸摘要、卡片 desc、一句話、帶走的問題也送評，對照各自依據的原文段落。
   - 回報忠實度、過度主張、完整度。
3. **修正草稿**（我）：依 Jev 與 lint 的標記改寫，每處寫下「原句 → 新句 → 理由」。
4. **讀者盲評**（我，sub agents）：
   - 每篇派 3 個 sub agent，各扮演一種讀者，只讀站上文字（不給原文），各自獨立作答、互不參考：
     - **行銷新手**：哪裡看不懂、哪個詞沒解釋、哪一步跳太快。
     - **忙碌主管**：30 秒內能不能說出本篇重點；一句話摘要與帶走的問題是否對得上內文。
     - **懷疑的同業**：哪句說得太滿、哪個數字缺出處、哪段像在推銷。
   - 每位讀者回報「讀完說出的重點」與逐段標記；我比對三份回報與原文意圖，挑出被誤讀或卡住的段落。
5. **站外 AI 審查**（你）：
   - 我每篇產出一份審稿文件 `docs/review/<短名>.md`：每段並排列出「原文依據（含前後文）→ 站上文字 → 我的修改與理由 → Jev 分數與盲評標記」，開頭附審查指示與檢核表，可整份直接貼給站外 AI。
   - 你把站外 AI 的意見貼回給我（或存成 `docs/review/<短名>.feedback.md`）。
6. **收尾**（我）：
   - 依站外 AI 意見修改，重跑步驟 1–2；有爭議的修改列給你決定。
   - 全部通過後，把該篇改為 `status: 'reviewed'`，並在 process-log 記錄。
