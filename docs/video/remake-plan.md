## 2. 旁白：自然、不念錯、低 AI 感

### 2.1 引擎
**D2（修訂）**：用 edge-tts（Azure 神經語音，原生台灣腔）。
- Gemini TTS：v3 已被駁回（非台灣腔），不用。
- 本機開源模型：沒有 GPU，今天來不及驗證，不用。
- 已實測：SSML 標籤無效，只能調 rate、pitch、volume，所以自然度只能靠**文稿寫法、切句和停頓**。

### 2.2 合成單位與停頓（回應懷疑者 #3）
**D4（修訂）**：**以「句」為單位合成**，一句是一個完整語氣，句尾自然降調。**不切成意群**，避免每個片段都降調、聽起來像一串句號。
- 句內停頓交給 TTS 依逗號自行處理。
- 句間停頓由程式控制：同一段內 0.30 秒、換段落 0.70 秒、刻意留白 1.5–3 秒（只用在 3 處：開場提問後、粒子收斂、22/22 點亮）。
- 每個 beat 的字幕剛好拆成 1–2 句，**每一行字幕對應一個合成句**，切換點就是句子邊界，不需要 WordBoundary（回應 #9）。

### 2.3 聲音與語速（回應懷疑者 #4）
- **預設沿用使用者上次指定的 HsiaoYu +19%**。
- 02:15–02:45 產出 4 份試聽樣本（HsiaoYu +19%／+12%、HsiaoChen +19%／+12%，同一段 n04＋n12，約 15 秒），放進 `docs/video/voice-ab/` 請使用者挑。
- **使用者 07:00 前沒回覆，就用預設**。之後換聲音只要重跑音訊（約 10 分鐘）加渲染（約 5 分鐘），時間軸會自動跟著變（D1-2）。

### 2.4 不念錯（回應懷疑者 #2）
把「能自動抓的」和「必須人耳抓的」分開處理，不讓 ASR 給出假安心：

| 錯誤類型 | 怎麼抓 | 能不能砍 |
|---|---|---|
| 多音字念錯（重、行、長、調、率…） | 用 `pypinyin` 列出稿中所有多音字所在的句子，產生**必聽清單**，人工逐句確認；念錯就在念法字典裡改寫用字 | **不可砍** |
| 英文縮寫和數字（SOV、GEO、AI、p.117、47） | 念法字典把 tts 一律改成國字或拆開的字母；字幕不受影響 | **不可砍** |
| 漏字、吞字、亂念、整句走樣 | ASR 回聽（faster-whisper small）：比對前先轉成繁體、去標點、數字轉國字，只比對「關鍵詞有沒有出現」加上 CER 超過 15% 時提醒。用途定位為**輔助**，不宣稱「已驗證不念錯」 | 可砍（排第 1 砍） |

- 念法字典 `pronounce.json` 只作用在 tts 字串，字幕照原文。
- 因為合成單位是句，字幕和 tts 用的是同一句的兩個版本，不需要做字詞對齊。

### 2.5 降低 AI 感
- 文稿改成口語，用「我」。句子以 12–25 字為主，不連續堆疊數字（同一句最多 1 個數字）。
- 句間停頓有長短變化（§2.2）。
- BGM：從 **Pixabay Music 挑 1 首**（免署名授權），存下授權頁截圖到 `docs/video/licenses/`；音量比旁白低約 20 dB，旁白時用 sidechain 閃避。**不加 whoosh 音效**（YAGNI，回應 #10）。
- 響度：整片一次 loudnorm（兩段式），不再逐句 loudnorm，保留句與句之間的自然起伏。

## 3. 敘事與腳本

沿用 review 文件中的三層旅程，但**依時長預算重寫**（回應懷疑者 #1）。

### 3.1 時長預算（硬性，程式自動檢查）

| 項目 | 預算 |
|---|---|
| 旁白字數（不含標點） | **≤ 520 字**（v0 稿 574 字，要再刪約 10% 以上，含換詞和 n15 拆句增加的字數） |
| 語速 | +19% 約 4.4 字/秒，約 118 秒；改 +12% 約 4.1 字/秒，約 127 秒 |
| 句間停頓加留白 | ≤ 28 秒 |
| 片頭淡入加片尾網址定格 | 1 秒加 6 秒 |
| **合計** | +19% 約 153 秒；+12% 約 162 秒，都 ≤ 175 秒 |

`build` 一開始就算出總長，**超過 175 秒直接停下來不渲染**。超時時處理順序：先刪字 → 再縮短留白 → 最後才加快語速。

### 3.2 腳本修訂原則
- 作品洞察併入 n03，不另加句子：「官方範例讓讀者先學操作；我讓你只做一件事：往下捲。」
- 數字規則（回應 #10）：
  - 字幕用最終建置的精確值，從 `facts.json` 讀取。
  - 旁白一律用口語概數，例如「一千五百多條」「一百多位作者」，寫死在稿子裡，不需要數字轉國字的程式。
  - `facts.json` 由 `npm run verify` 的輸出解析產生。
- n12 的 FAIL 畫面（回應 #6）：
  - 不切換舊 commit。改在 scratchpad 複製單一資料檔，把頁碼改成 117，只跑引文比對腳本，取得真實的紅字輸出（時間盒 20 分鐘）。
  - 超時的話，改用 `process-log.md` 記載的原始錯誤文字做成終端卡，旁白說「當時的錯誤」，不宣稱是即時畫面。

### 3.3 字幕與旁白對齊、易懂性（回應用戶倡導者）

**字幕與旁白對齊**
- 字幕只能由 tts 原句**刪減**產生，不另外換詞。
- 唯一例外是數字格式：旁白念「一千五百多條」，字幕寫「1,500+ 條」，兩者語意相同。
- build 時自動檢查：字幕去掉數字以後的每個字，都必須依序出現在對應 tts 句**套用念法字典之前的原句**中。

**每句最多 1 個事實**
- n15 拆成兩句：「全站都是靜態頁面，沒有資料庫，也不連外部服務。」「網頁裡的每段程式都鎖了指紋，被改過就不執行。」
- 47 頁、Cloudflare、SHA-256 只放在畫面小字。

**n12 只講一個錯誤（p.117）**
- 拆成兩句念：「AI 寫成第一百一十七頁。」「原文其實在第一百一十九頁。」符合每句最多 1 個數字的規則。
- 「硬說成對立」從旁白移除，避免說到卻沒有畫面。

**換掉評審聽不懂的詞**

| 原詞 | 問題 | 改法 |
|---|---|---|
| 審查代理 | 行銷人會聽成廣告代理商 | 刪除 |
| 衡斷力的天平 | 自創詞，聽起來像把「判斷力」念錯 | 改說「人和 AI 的判斷天平」，篇名只出現在字幕 |
| 十一個層次 | 沒說是哪些層 | 改說「從電視到短影音，十一種媒體每一種都做」 |
| 官方範例 | 沒交代是誰的範例 | 改說「很多互動電子書，要你先學怎麼操作」 |
| 雜湊鎖 | 工程術語，評審接收不到價值 | 改說「鎖了指紋，被改過就不執行」 |

**靜音也看得懂**
- FAIL→PASS 的紅綠對比，以及 117 和 119 這兩個數字，字級 ≥ 32px，各停留 ≥ 2 秒。
- 每一段的核心訊息都要有畫面上的大字，不能只靠旁白。

**進度列狀態**

- n04–n05：「① 全書」亮。
- n06–n07：「② 一篇」亮。
