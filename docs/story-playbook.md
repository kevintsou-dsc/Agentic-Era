# 故事頁製作標準流程（Story Playbook）v1

> 2026-10-26。整理 a08、a10、a11、a13 四頁的建置與多輪修改經驗。
> 寫作規則細節見 `docs/story-guide.md`（本文件引用時寫「guide §N」）。本文件只講**順序、判斷與檢查**，目標是每篇一次寫對、少重工、少 token。

## 0. 一篇的完整流程（7 步）

| 步驟 | 做什麼 | 產出 | 工具 |
|---|---|---|---|
| 1 盤點 | 產生原文盤點表，讀一次全文 | `content/inventory/aNN.md` | `node scripts/extract/inventory.mjs aNN` |
| 2 定調 | 一句話主張、故事弧線、每個原刊圖表的去處 | 場景表（腦中或草稿） | §2 決策表 |
| 3 選圖 | 依「語意」選呈現方式 | 每個場景的 graphic 類型 | §3 對照表 |
| 4 撰寫 | 一次寫完 `src/data/stories/aNN.ts` | 故事檔 | 以 a10／a11／a13 為範本 |
| 5 自動檢查 | 逐字比對、lint、型別、建置 | 全部 ✓ | `npm run story:check` |
| 6 自我審查 | 對照 §5 清單逐項打勾 | 修正後的故事檔 | §5 清單 |
| 7 初評與紀錄 | Jev 初評、修旗標、改 status、寫紀錄、commit | `status: 'judged'` | `jev_review.py`、`docs/process-log.md` |

## 1. 盤點原文（只讀一次）

先跑 `node scripts/extract/inventory.mjs aNN`。盤點表列出：

- 標題、作者、紙本頁碼範圍
- 章節小標（含頁碼）：決定故事弧線的骨架
- **原刊圖表清單**：圖號、圖說、頁碼、是照片還是向量圖表／表格、圖檔路徑與尺寸、附近的 QR 連結
- **圖中文字**（figtext）：向量圖表的標籤與數字，逐字比對用
- **數據句**：含 %、萬、億、倍、秒、人次等的句子，並標示是「統計」還是「作者經驗／舉例」
- **條列訊號**：「第一、第二」「首先、其次、最後」、分號串列、表格列
- **案例清單**：品牌、作品、活動名稱，以及有沒有圖片與連結
- **註解連結**：細節卡的 `links` 來源

讀完盤點表後，**只讀一次全文**（`content/fulltext/aNN.md`），邊讀邊在盤點表上標：哪段是總覽、哪段逐項展開、哪段是作者小故事、哪些概念在不同章節重複出現。之後寫作只回查特定段落，不要重讀整篇。

---

## 2. 定調：先決定「放什麼」，再決定「怎麼放」

### 2.1 必備清單
- 一句話主張（`oneLiner`）：策展者整理，40 字內。
- 故事弧線：① 開場 ④ 框架 ⑥ 收束必備（guide §2）。
- **原刊每一張圖表、表格、流程圖都要有去處**。照片放進卡片或細節卡；QR 改成連結。
- 帶走的問題（`asks`）：優先用原文的問句或行動清單。

### 2.2 去重（寫之前就做）
列出每個「概念」出現在哪幾頁。同一概念只畫一次，放在講得最完整的那段；另一處改畫該段獨有的內容（guide §5「同一篇不要重複畫同一個概念」）。

### 2.3 主文與圖的分工
- 主文：論點完整、可單獨讀懂；原文的數字、案例細項、圖上的細項都寫進主文並附 `src`。
- 圖：讓讀者「看見」主文講的關係或數量。
- hover（`extra`）：只放策展補充，例如定義、由來、例子、對品牌的意義。
- 細節卡（`more`）：更長的原文段落、案例圖片、影片與網站連結。

## 3. 選圖：依語意，不依資料長相

| 原文在講什麼 | 用什麼 | 範例 |
|---|---|---|
| 有母體的統計數字（單一、震撼） | `bignum`（一定帶單位） | a10 +20% YOY |
| 「多少比例的人」 | `bignum` ＋ `people` 人形圖 | a11 65% Z 世代 → 20 人中 13 人 |
| 幾個統計值互相比較 | `bars`／`hbars` | a11 近三屆金曲獎收視 |
| 不同族群在同一組指標上的差異 | d3 `groups` | a11 平成 Retro 三個族群 |
| 跨數量級的倍數 | d3 `logrange` | a13 CPM／CPC／CPA |
| 公式或運算（A − B、A ÷ B） | 能演出運算的 d3 圖 | a13 ESOV 減法 |
| 循環、惡性循環、生態系 | d3 `flowloop` | a10 Doom Loop、a08 IP 生態系 |
| 時代演進、模型比較（起點改變） | d3 `stages` | a10 AIDMA → AICAS |
| 範圍逐圈擴大 | d3 `rings` 同心圓 | a13 四種競爭 |
| 資源分配、集中 vs 分散、累積 vs 消耗 | d3 `allocate` 點陣（標示意） | a13 預算分配 |
| 有先後順序的轉變、階段演進、遷移 | `list` 加 `layout: 'timeline'`（4 項以內橫向、5 項以上直向，標題寫「階段｜名稱」會拆成節點標籤） | a06 信任轉移、a20 三次遷移、a11 五個階段 |
| 流程被壓縮、步驟被吸收 | `art` 壓縮動畫（長鏈收成短鏈） | a18 顧客旅程壓縮 |
| 有層次的框架（由底到頂、由淺到深） | `layers` | a13 Share of Choice Context |
| 兩軸判斷 | `matrix` | a10 媒體布局矩陣 |
| 彼此並列、沒有順序的項目 | `list` | a13 干擾場域 |
| 表面現象 → 背後真因（每項都是「看似…其實…」） | `list` 加 `flip: true` 翻面卡（正面 title＝表象，背面 desc＝真因） | a05 看似／其實 |
| 原文依固定格式展開的案例（情境—方法—模擬），篇幅長 | `case`：每個案例一個捲動段落，主文標 `tag`（情境／方法／模擬），右側依序換畫面；要比較的素材並排在情境畫面，不藏進細節卡；最後用一張總結 | a12 五個模擬案例 |
| 3–6 個案例，各有圖片或數字 | `hscroll` 橫向捲動（每篇最多一個） | a08 六個現場、a11 國際案例 |
| 單一深度案例 | `prose` ＋ 圖片 ＋ 細節卡 | a11 ORANGE RANGE |
| 虛擬人物、Persona、具名的消費者對照 | `art` 人物檔案（肖像＋心聲＋排序，不要用框框清單） | a12 Lisa／Cindy |
| 一個主控者分派給多個專家（Orchestrator–Worker） | `art` 分工圖（主控在中間、專家並列，分派與回傳兩種流向），不要用 `flowloop` 循環 | a12 Super Agent |
| 作者親身經驗、小故事 | `art` 分格插畫（不要用 bignum） | a13 磁吸支架 |
| 作者的金句 | `quote` | 每篇收束 |

**每一步亮起的東西，必須正是那段主文在講的東西。**先逐段寫下「這段講什麼」，再決定圖的每一步；圖的元素數（例如四個節點）不等於段數時，不要讓第 N 段機械地點亮第 N 個元素。a12 第一版的 flowloop 有四個節點、主文三段，結果第 2 段講三位專家，圖上卻亮「分派任務」，第 3 段講四個價值，圖上卻亮「判斷答案品質」，而且三位專家根本沒畫出來。

新的圖表元件，根元素一律加 `stage` class：捲動版面靠 `.graphic > .stage` 把圖限制在半欄寬，漏了就會撐滿整頁、壓到主文卡（a12 案例第一版）。元件內的 class 名稱要加元件前綴（例如翻面卡用 `fc-`）。`.card`、`.flip`、`.step` 這類通用名稱會吃到 Scenes 與 global.css 的樣式，翻面卡第一版就因此多出外框、尺寸不一，也翻不了面。

需要新的 d3 圖時：先確認上表沒有合適的，再新增 `D3Chart` kind。新圖要同時加四處：`story.ts` 型別、`d3charts.ts` builder、`D3Chart.astro` 的 CSS 與純文字 fallback，以及 `lint-stories.mjs` 的說明框檢查。

## 4. 撰寫故事檔：一次寫對的規則

### 4.1 主文（beats）
- 每段 30–140 字，以句末標點結束；全篇 500–3,000 字。
- 每段至少一則 `src`，`text` 必須是原文**逐字**片段，`page` 要對（看盤點表的頁碼標記）。引用跨頁句子時，拆成兩則 `src`。
- **圖上的數字寫進主文時，`src` 要包含圖表標籤或 figtext**（例如 `'適合拍照打卡'`、`'61.9%'`）。只引內文會被 Jev 判為出處不足。
- 寫作者全名，不寫「本文」「作者」以外的代稱；不加原文沒有的因果。
- 「某某認為」這類歸因句，要引到原文表達這個看法的那一句，否則 Jev 會判為出處不足（a14 試做經驗）。
- 條列內容拆成多段時，每段都要能單獨讀懂：第一段先交代「有幾項、在講什麼」，不要用「第一是…」開頭（a14 試做經驗）。
- **總覽句要把項目名稱寫出來**：「作者提出三個挑戰」「有五個方向」這種只說數量的句子，Jev 會判為不完整；改寫成「三個挑戰：A、B、C」，並把各項名稱（小標或圖表標籤）加進 `src`（第二批經驗，a01、a05）。
- **轉場句與 hscroll 開場句也要有原文依據**：策展者自己串起來的轉場（「以下三個案例都在講同一件事」）會被判為出處不足。改用原文的小標或結論句組成（例如三個案例的小標並列），並把小標加進 `src`（第三批經驗，a17）。
- **案例卡片的情境詞要附出處**：卡片寫到「雙薪家庭」「45 歲以上客群」這類設定時，要引原文的情境段落，不只引結果數字（第三批經驗，a12）。
- **只出現在圖表上的內容**：Jev 的原文脈絡已會讀取 figtext（同頁圖表文字），但圖上的相對位置（「右上角」「左下角」）無法被驗證，不要寫進主文；直接寫「當 A、B 時，原圖給的做法是…」，並把格子標題與每個做法標籤都列進 `src`（第四批經驗，a10）。
- **原文用「我」時，少用「作者姓名＋發現／認為」當主詞**：改成直接陳述觀點（「真正把 AI 帶進工作後會看到…」），或引到原文「我發現…」那一句（第二批經驗，a05、a09）。

### 4.2 逐段揭示（`at`）
- **先決定這段主文在講第幾項，再設 `at`**。總覽段同時提到所有項目時，全部 `at: 1`；總覽後逐項說明的，從第 2 段開始對應（layers 用 `at`）。
- 寫完逐段核對：捲到第 k 段時，右邊亮起的正好是這段在講的東西。

### 4.3 圖表
- 圖說 `source`：「圖：〔原圖說〕｜資料來源 〔原出處〕，作者〈短標題〉紙本 p.xx」。策展者自製的圖標「依原文文字整理製圖」，示意圖標「示意，非實際比例」。
- 場景 `src`：逐字比對用，不顯示；畫面上的出處只有圖說 `source` 一行。`figures`：圖中數字的逐字比對依據，不顯示。
- d3 圖每個可互動元素都要有 `extra`，2–4 句、50–120 字，不放原文、不加數據（guide §5.1）。
- 圖表元素上的細節用 `more`，會自動以 overlay 呈現，不佔版面。

### 4.4 圖片
- 只用 `content/figures/aNN.json` 列出的 `/fig/aNN/*.webp`，`w`／`h` 照抄 JSON。
- 確認圖片內容與圖說一致：圖說可能被抽圖腳本誤配，必要時打開圖片確認（例如 a11 p89-2 是芬達、不是日清）。
- 卡片沒有圖時，細節會自動攤在卡片上；不要硬塞不相關的圖。

### 4.5 狀態
新寫的故事 `status: 'draft'`；Jev 通過後改 `judged`。不要自行標 `reviewed`。

## 5. 自我審查清單（自動檢查通過後，逐項打勾）

**內容**
- [ ] 只讀主文，能說出這篇的主張、一個理由、一個做法。
- [ ] 原刊每張圖表、表格、流程圖都有去處；案例圖片與連結都放了。
- [ ] 沒有兩張圖在講同一個概念。
- [ ] 主文提到的關鍵數字，圖上都看得到；圖上的重點，主文都有一句話說出意義。

**呈現**
- [ ] 每張圖的形式對應語意（§3 對照表），不是兩根長條硬比。
- [ ] 統計數字才用大數字／長條；作者經驗與舉例不用。
- [ ] 大數字都帶單位；「多少比例的人」配人形圖。
- [ ] 每個 `at` 都對得上該段主文（逐段捲一次）。
- [ ] 同一篇最多一個 hscroll；相鄰場景沒有連續兩個同類型。

**說明與出處**
- [ ] d3 每個元素都有實質的 `extra`（不是重複標籤），而且沒有不可靠的年份、數字、人名。
- [ ] 每張圖只有一個出處按鈕；說明框裡沒有原文或頁碼。
- [ ] 外部連結都來自原文註解或圖片旁的 QR。

## 6. 自動檢查與初評（一個指令跑完）

```bash
npm run story:check
```

它依序執行：逐字比對（verify-quotes）、作者比對（verify-meta）、主文與說明框 lint（lint-stories）、型別檢查（只看故事與元件）、建置與站內連結檢查。全部 ✓ 才進下一步。

Jev 初評：

```bash
cd ../jev-test && .venv/Scripts/python "../決策智慧vibecoding比賽/scripts/review/jev_review.py" roundN aNN [aNN ...]
```

- 被標記的段落多半是「出處不足」：補上更貼近的 `src`（尤其是圖表標籤），不要改寫成更模糊的句子。
- 修完再跑一次。0 標記才把 `status` 改為 `judged`。

## 7. 省 token 的做法

1. **盤點表先行**：用 `inventory.mjs` 取代反覆搜尋全文；全文只讀一次。
2. **一次寫完故事檔**：以 Write 整檔寫入，不要逐段 Edit。
3. **一個指令跑完所有檢查**：`npm run story:check`，只看 ✗ 的輸出。
4. **修正用最小 Edit**：只改出錯的 `src` 或段落，不重寫整檔、不重讀檔案。
5. **同類型批次處理**：同一章節（intro／people／model／ai）連續做，共用範本與說明框寫法；Jev 一次跑多篇。
6. **不重造元件**：§3 的元件能用就用；新 d3 圖只在語意真的對不上時才做。
7. **不開瀏覽器自檢**：視覺由使用者人工檢查；自動檢查與建置後的 HTML grep 足以確認結構。
