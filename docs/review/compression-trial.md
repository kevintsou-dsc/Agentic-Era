# 過度濃縮：兩篇試跑結果

2026-11-08。作法見 [compression-plan.md](compression-plan.md)。試跑的兩篇：
- 〈信任｜為何成為 AI 時代最難複製的競爭力〉
- 〈People Model 讓消費者研究變成一場隨時能開口的對話〉

## 結論

改寫 24 則泡泡後，盲讀的卡住點減少約四成五：〈信任〉11 → 6，〈People Model〉23 → 13。兩位讀者都卡住的泡泡減半。

沒改的泡泡分數幾乎不變，可以當作對照組，說明改善來自改寫，不是讀者打分的起伏。

代價是篇幅：
- 改寫過的泡泡平均增加 48%，超過原訂上限 30%。
- 整篇主文只增加約 18%，因為只改被標出的泡泡。

## 忠實度覆核

由另一位代理人只比對原文和新句。

| 判定 | 則數 | 說明 |
|---|---|---|
| ok | 18 | 新加的內容在原文找得到 |
| 一般背景 | 2 | 「YouTuber」「台北豪宅」身分說明；MAE、RMSE 的中文全名 |
| 說得比原文強 | 4 | 都很輕微，已全部修正 |

修正的 4 則：
- 〈信任〉「信任庫」：拿掉直接下的定義，改回原文帶「或許」的語氣，另起一句寫。
- 〈People Model〉M04：補回「往往」。
- 〈People Model〉M17：「二選一」改成「比較優劣」。
- 〈People Model〉M37：「五個案例指向同一件事」改成「回到這些案例背後的主張」。這段在原文裡是作者的主張，不是從案例歸納出的結論。

另外兩處小偏差也修正了：M14 多加的「市場」二字，以及 M20 倒裝的「所以」。

修改後盲讀用的是忠實度修正之前的版本，6 則句子後來又小改過，不影響上表的比較。`npm run story:check` 全過。

## 還沒解決的，以及全站作法的建議

1. **術語卡住最多，改寫也最難消除**（S4，17 → 13）。
   - 例子：「Agent」、「微調大型語言模型」、「資料點」、「轉換」、MAE。
   - 主文已經補了一句交代，但新手讀者仍要定義。
   - 建議：每篇第一次出現的核心術語，在主文用一句白話帶過。更細的解釋放進細節卡或術語提示，不再擴寫主文。
2. **原文本身的概念詞**：例如「信任庫」「競爭的規則」「信任的生產機制」。讀者仍覺得像口號，但這是作者的論點，主文不該替作者具體化。建議維持原樣，必要時在細節卡引用原文完整段落。
3. **篇幅上限要調整**：原訂每則 +30%，實際中位數 +48%（+14% 到 +106%）。補回省略的環節，常常需要一整句。
   - 建議改成兩條：每則以 140 字為上限（現有檢查已擋）；每篇主文總增幅不超過 25%。
4. **沒改到的泡泡也冒出新卡點**：〈信任〉M05、M16，〈People Model〉M16。
   - 這三則修改前兩位讀者都給 4 分，這輪沒改；換了一批讀者後才被標出，屬讀者間的差異。
   - 建議：全站做時，修改前盲讀只要任一讀者給 4 分以下且標出症狀，就一併判定。
5. **樣本小**：每篇只有 2 位讀者，數字會有起伏。全站建議維持 2 位，但看「兩位都卡住」和「改寫泡泡 vs 對照泡泡」的差距，不只看平均分。
6. **初篩腳本的「句間無連接詞」太粗**：只看句首 12 個字，改寫後在〈信任〉反而變多（10 → 12）。全站時只當排序參考，以讀者回報為準。
