# 主文泡泡「過度濃縮」檢查與修正

2026-11-08。

**問題**：主文是原文的改寫。有些泡泡壓得太緊，每個字都忠於原文，但沒讀過原文的讀者會讀不順，或看不懂。

**試跑**：〈信任｜為何成為 AI 時代最難複製的競爭力〉與〈People Model 讓消費者研究變成一場隨時能開口的對話〉。用 AI 盲評比較修改前後的差異；確認改動幅度後，再擴及全站。

## 一、定義：七種症狀

| # | 症狀 | 例子 |
|---|---|---|
| S1 | 少了主詞或對象 | 不知道是誰在做、對誰做 |
| S2 | 因果跳步 | 原文 A → B → C，泡泡只剩 A → C |
| S3 | 指稱懸空 | 「這套能力」「此一轉變」，指的東西只出現在原文前文 |
| S4 | 術語沒交代 | 第一次出現的概念沒解釋 |
| S5 | 壓成口號 | 四字詞、名詞堆疊 |
| S6 | 段落斷裂 | 相鄰兩則之間少了銜接 |
| S7 | 缺少適當的轉折與連接詞 | 同一則裡句與句之間少了「因此」「但」「也就是說」「例如」，讀者要自己猜兩句的關係 |

## 二、流程

1. **腳本初篩**
   - 指令：`node scripts/review/compression.mjs <標籤> <短名…>`
   - 做的事：給主文泡泡編號；計算濃縮比（泡泡字數 ÷ 出處所在原文整段的字數）。
   - 標出三種徵兆：
     - 濃縮比低於 0.35。
     - 句間無連接詞（S7）。
     - 指代開頭（S3）。
   - 結果只當提示，不自動修改。
2. **修改前盲讀**：2 位讀者 × 2 篇，題目見第三節。
3. **判定**：主導者把每個卡住點對照原文，分成兩類：
   - **過度濃縮**：原文有交代、泡泡省掉了，要修。
   - **原文本來就難**：主文不修，必要時在細節卡補充。
4. **修改**：依第四節的原則改寫，每處記錄「原句 → 新句 → 症狀 → 原文依據」。
5. **忠實度覆核**：另派代理人只看原文 → 新句，確認沒有說得比原文強、沒有加入原文沒有的結論。
6. **修改後盲讀**：換一批沒看過舊版的讀者，角色與題目完全相同。
7. **比較前後**：
   - 平均通順分。
   - 4 分以下的泡泡數。
   - 卡住點數，以及兩位讀者都卡住的泡泡數。
   - 誤讀數。
   - 整篇通順分。
   - 讀完說出的重點是否對上一句話摘要。

## 三、盲讀題目（修改前後相同）

**讀者**：
- **行銷新手**：剛進廣告代理商一年的 AE，懂基本行銷名詞，但不熟 AI 與產業術語。
- **非行銷背景的上班族**：科技業工程師，對行銷與廣告陌生，習慣讀邏輯清楚的文件。

**只讀**：`content/review/compression/<短名>.<標籤>.reader.md`。不給原文，也不讓讀者知道這是修改前或修改後。

**回覆**：寫成 JSON。
```json
{
  "takeaway": ["三句話重點，不抄原句"],
  "overall_fluency": 1-10,
  "bubbles": [{ "id": "M01", "score": 1-5, "stuck": false }],
  "stuck": [{ "id": "M07", "types": ["S2","S7"], "quote": "節錄原句（20 字內）", "why": "為什麼卡住", "paraphrase": "我以為這句的意思是…" }]
}
```

**泡泡分數**：

| 分數 | 意思 |
|---|---|
| 5 | 一讀就懂，和前後文接得順 |
| 4 | 懂，但有一點要想 |
| 3 | 要讀兩次 |
| 2 | 讀完還是不確定意思 |
| 1 | 看不懂或接不上 |

**誤讀**：讀者的 paraphrase 與原文意思不同。由主導者對照原文判定。

## 四、修改原則

- **只補回原文裡被省掉的那一環**：主詞、條件、因果連接詞、轉折詞、一個例子、一句定義。盡量用原文的說法，不加原文沒有的主張。
- **篇幅**：
  - 每則增加不超過約 30%。
  - 單句不超過 60 字。
  - 每篇主文維持 500–3,000 字。
  - 太長就拆成兩則。
- **出處**：每則仍要有逐字出處；`npm run story:check` 必須全過。
- **原文本來就難的**：主文維持忠於原文，白話說明放進細節卡。

## 六、全站規則（2026-11-10，依試跑修訂，取代第四節的篇幅條款）

- **篇幅**：
  - 每則不超過 140 字，`story:check` 會擋。
  - 每篇主文總增幅不超過 25%。
  - 不再設單則增幅上限。
- **要判定的泡泡**：修改前盲讀中，任一讀者給 4 分以下且標出症狀的泡泡，都要判定；兩位讀者都卡住的，一定要改。
- **術語（S4）**：第一次出現的核心術語，主文只用一句白話帶過，不展開；更細的解釋不擴寫主文。
- **作者自己的概念詞**：例如「信任庫」「競爭的規則」，主文不替作者具體化，維持原文說法。
- **忠實度覆核**：分批由另一位代理人逐則判定 ok、一般背景、說得比原文強；說得比原文強的一律修回。
- **盲讀題目**：統一放在 `content/review/compression/blind-prompt.md`，修改前後都用這一份。試跑時是把題目直接寫在派工訊息裡，內容相同；只有 stuck 的門檻從「3 分以下或覺得卡住」改成「4 分以下且說得出哪裡不順」。
