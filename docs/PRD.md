## 1. 背景與目標

### 1.1 比賽
《決策智慧》10 週年 Vibe Coding 競賽。要交四樣東西：公開網址（免登入）、3 分鐘介紹、製作歷程、部署與資安自評。

| 評分項 | 配分 | 本作品的對應策略 |
|---|---|---|
| 閱讀體驗與內容策展 | 40 | 從讀者手上的問題切入，3 分鐘內完整體驗一輪；策展層與原文明確分層；引文自動逐字核對 |
| Vibe Coding 實作力 | 30 | 製作歷程完整記錄「AI 初稿 → 人工判斷 → 修改」；建置閘門確保沒有壞功能和斷鏈 |
| 部署思路與資安自評 | 15 | 靜態站＋安全標頭＋repo 衛生＋授權白名單，五個面向如實自評 |
| 創意與洞察 | 15 | 「為一個決策而讀」：把全書主張「AI 整理、人判斷」做成閱讀方式本身 |

### 1.2 產品目標
- **G1** 第一次來的讀者 10 秒內知道從哪開始，3 分鐘內完成一輪「問題 → 多篇觀點 → 換你判斷」。
- **G2** 想找特定文章或同事文章的讀者，第一屏就找得到入口，2 次點擊內到達。
- **G3** 每一則引文、數字、標題、作者、職稱都可回溯到刊物頁碼，正確率 100%，由建置閘門保證。
- **G4** 22 篇文章每篇至少在一道題目中被直接引用，對所有作者公平呈現。

### 1.3 非目標
- 不做 AI 聊天問答，不串即時 LLM，不設後端。
- 不做 3D 場景（官方範例已經做過兩個，而且 3D 會犧牲閱讀與手機效能）。
- 不重現紙本翻頁。
- 不蒐集任何使用者資料。

## 2. 核心洞察與差異化

**洞察**：四個官方範例都在回答「這本書可以長成什麼形狀」（空間、3D 塔、影像、翻書），全都以書為中心。這本刊物叫《決策智慧》，全書反覆主張 AI 負責整理、人負責判斷（衡斷力），以及「先看見顧客在哪裡猶豫」。所以最貼近原意的讀法是**帶著一個決策來讀**。

**與「螺旋書塔」主題線索的差異**（影片用的一句話）：
> 書塔告訴你哪幾頁談到「信任」；我們讓 4 篇文章針對你的問題提出觀點、拿出證據，然後換你判斷。

**每道題目的三件套**（缺一項就不上線）：①**關係標籤**（呼應／補充／不同側重）②**證據**（原文引文與數字，附紙本頁碼）③**換你判斷**（問讀者自己的情境，給出有內容的回饋）。

## 3. 使用者與情境

| 角色 | 情境 | 成功標準 |
|---|---|---|
| R1 冷啟動評審 | 收到網址，筆電打開，沒讀說明，約 3 分鐘 | 完成第 0 題一輪，並看得出跟範例不同 |
| R2 找特定文章的主管或同仁 | 想看某位同事寫的那篇 | 首頁 → 目錄 → 文章，2 次點擊內 |
| R3 手機讀者 | 從分享連結直接進入單篇 | 知道這篇屬於哪一章、出現在哪幾題，並能繼續讀 |
| R4 有實際決策的行銷主管 | 正要開預算或 AI 導入會議 | 找到對應題目，帶走 2–3 個可用的判斷問題與出處 |

**驗收情境（評審旅程）**：一位同仁打開網址，不讀任何說明，在 3 分鐘內完成第 0 題，並找到自己同事的文章。

## 4. 資訊架構

```
/                       首頁
/q/0 … /q/N             題目頁（圓桌）
/a/<slug>               單篇深讀頁（整理｜全文 兩個分頁）
/a/<slug>?from=q3       從題目進入時顯示「來自：〈題目〉」
/toc                    目錄（依 Intro/People/Model/AI 分章）
/paths                  全書三條主線（P1）
/about                  關於本作品：策展方法、出處與著作權、隱私說明、製作歷程連結
/llms.txt               機器可讀摘要（P1，自動產生）
```
URL slug 一律用 ASCII（例如 `p44-trust`，取紙本起始頁加英文關鍵字）。

## 5. 功能需求

### 5.1 首頁（P0）
第一屏線框：
```
2026 決策智慧｜Agentic 時代：重塑品牌與人的真實距離

品牌離 AI 越近，會離人越遠嗎？
22 篇觀點、30+ 位作者。為一個問題讀，或依章節讀。

[ 開始：這本書的核心問題 → ]                 ← 唯一的主按鈕
  約 3 分鐘｜4 篇文章回答同一個問題，最後換你判斷

依章節或作者找文章 →                          ← 文字連結，不做成按鈕
```
第一屏以下：其他題目卡片（題目＋回答的文章數＋預估時間），以及一句說明網站怎麼做（連到 /about）。

### 5.2 題目頁／圓桌（P0）
- 頂部：題目、為什麼這題重要（策展者寫，2 句）、預估時間。
- 主體：3–5 張**觀點卡**。桌面版以圓桌排列，手機版改為縱向卡片流。每張卡分三層，視覺上明確區分：
  1. **整理**：策展者用第三人稱寫的摘要，不加引號，卡片角落標「整理：策展者」。
  2. **原文**：引號＋不同的字體樣式＋「紙本 p.xx」，每則 ≤ 80 字。
  3. **證據**：1 個數字或案例，附頁碼。
  卡頭顯示該篇所有作者的姓名與職稱、章節色，以及「回答這題」或「延伸閱讀」的標記。
- 卡片之間的**關係標籤**：呼應／補充／不同側重，寫成「與 吳宗霖〈重建 SOV〉補充」這種格式。每條關係都有兩邊的原文依據，經人工核可。**除非原文明確反駁，否則不標示對立。**
- 底部「**換你判斷**」：問讀者自己的情境，用原生 radio 作答，可以跳過。選完後顯示策展者預先寫好的回饋，回饋要指向書中具體的做法與頁碼。
- 「下一題」與「目錄」永遠可見，不必先作答。
- 介面上不出現文章編號，也不用「XX 說：」句式。

### 5.3 單篇深讀頁（P0）
- 頁首：章節色、標題（以內頁為準）、全部作者與職稱、紙本頁碼範圍、「整理約 2 分鐘｜全文約 N 分鐘」。
- 從題目進入時固定顯示「來自：〈題目〉 ←」；直接進入時顯示「本篇屬於 People 章｜出現在 2 道題目」並附連結。
- **整理分頁**（預設）：為什麼讀（取 xlsx「必看三要素」再策展）、3 個關鍵論點、關鍵數字、可帶走的判斷問題。末端放「繼續讀全文」按鈕。
- **全文分頁**（依 K2 決定）：抽取後經人工校正的全文，段落旁標示紙本頁碼。
- 結尾有兩個出口：「回到來的那一題」與「這篇也回答了哪幾題」。

### 5.4 目錄（P0）
依 Intro/People/Model/AI 分章，每篇列出標題、全部作者姓名與職稱、紙本起始頁、出現在哪些題目。作者姓名篩選屬 P1。

### 5.5 關於頁（P0）
策展方法（含 AI 與人的分工）、出處與著作權聲明、編輯團隊（不含聯絡方式）、隱私說明（不蒐集資料、只用 localStorage 記錄已讀）、製作歷程與原始碼連結。

### 5.6 P1
已讀標記（localStorage，只存 articleId、questionId、選項）；全書三條主線（真實與信任／判斷力／Agent 經濟，取自 xlsx 的全書導讀）；作者篩選；全部讀完後的收尾畫面；llms.txt 與 JSON-LD（由 sources.json 自動產生）。

### 5.7 P2（做不完整就不上線）
條件式立場光譜（只用在有明確兩端軸的題目）；判斷結果匯出成 PNG；「給 AI 讀的版本」切換（呼應 AX／GEO）。

### 5.8 狀態規則
- 進度為 0 時不顯示；localStorage 不可用時，整個進度元件隱藏。
- `prefers-reduced-motion` 開啟時關閉所有轉場。
- 404 頁提供回首頁與目錄的連結。

### 6.2 每篇策展欄位（`content/articles/<slug>.json`，用 zod schema 驗證）
`id, slug, chapter, printPageStart, printPageEnd, titleInner, titleXlsx, titleToc, authors[{name, nameEn, title}], whyRead, keyPoints[3], keyFigures[{text, page}], quotes[{text, page}], takeaways[], fulltextPath, readMinutes`

### 6.3 正確性規則
- **標題**：以文章內頁標題為準（K4）；xlsx 與目錄的差異登記在 `content/title-exceptions.json`。
- **頁碼**：一律寫成「紙本 p.xx」，由單篇起始頁換算（起始頁見 `docs/design-review/facts-verified.md`）。
- **引文與數字**：必須是 `content/fulltext` 的逐字子字串（正規化後比對）。
- **作者與職稱**：以內頁為準，跟 xlsx 不一致的地方登記在例外清單。
- **關係標籤**：每條都要附兩邊的引文，並經人工核可（`approvedBy: human`）。
- **個資排除**：版權頁的公關 Email 不得進入 content 和 repo。

### 6.4 內容管線
1. `scripts/extract`（Python、PyMuPDF）：直接從 OneDrive 路徑讀單篇 PDF，依區塊座標「先欄後列」排序，排除頁眉、頁碼與註解，輸出 `content/fulltext/<slug>.md`，並標上頁碼。
2. 人工校正：每篇 15–25 分鐘，22 篇共 6–9 小時；抽樣 ≥ 10% 段落和 PDF 畫面比對。
3. AI 產出策展初稿（整理、論點、引文候選、回饋文字）→ 人工審定 → 在製作歷程記錄 diff 與理由。
4. `npm run verify` 閘門（見 §8）。

## 7. 視覺與互動規格

### 7.1 視覺語言
沿用刊物識別，詳見 `Content-Factory/creative-brief.md`。
- 牛皮紙底，同時保證文字對比 ≥ 4.5:1。
- 鉛筆素描（人）× ASCII 字元（AI）並置：作者觀點用手繪線條，結構化資料與頁碼用等寬字。
- 章節色：People 萊姆綠、Model 粉紅、AI 淺藍，Intro 用中性色。品牌色只用在色塊與線條上，色塊上的文字一律用深色。
- 鐳射漸層只用在主標與「換你判斷」的回饋卡。
- 字體：Noto Sans TC（子集化）、Montserrat、Pixelify Sans（頁碼與標籤）。

### 7.2 互動
CSS ＋ View Transitions 做頁面轉場；圓桌入場動畫 ≤ 600ms；不做捲動劫持；全流程可用鍵盤操作。

## 9. 部署與資安

### 9.1 部署（K3，建議 Cloudflare Pages）
- Cloudflare Pages 以 Git 整合部署，repo 和 CI 都不需要 token。使用預設網域 `*.pages.dev`，production 只從 `main` 部署。
- 11/20 起凍結 `release`；繳交前 24 小時不推 production；網址至少保留到 2026-12-31。
- `_headers`：CSP `default-src 'self'`（框架產生的 inline 以 hash 允許）、HSTS、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`frame-ancestors 'none'`、`Permissions-Policy` 全部關閉。
- 備案 GitHub Pages：只能用 meta CSP，HSTS 等標頭無法設定，需在自評中寫明這個限制。

### 9.2 Repo 衛生（高風險）
- **git root 固定在專案資料夾**。上層工作區放有其他專案的設定檔，**禁止在上層 git init，也禁止整包上傳**（K8，使用者已確認上層安全）。
- `.gitignore` 採白名單式：先寫 `*`，再開放 `site/`、`content/`、`scripts/`、`docs/`、設定檔。
- pre-push 檢查：gitleaks 為 0 筆；`git ls-files` 不得出現 `.pdf/.indd/.idml/.xlsx/.ai/.psd`，也不得出現含 `private_key` 的 `.json`；dist 不輸出 sourcemap。

### 9.3 資安自評五個面向（繳交文件骨架）
1. 內容與圖像授權（K7：使用者確認所有素材皆可使用；網站仍標註圖片出處，案例截圖沿用刊物原有的「資料來源」說明）
2. Repo 衛生與機密掃描結果
3. 依賴（`npm audit` 不得有 high 以上漏洞、鎖定版本、執行期 0 個第三方網域）
4. 部署與安全標頭（附 securityheaders.com 或 Mozilla Observatory 檢測截圖）
5. 隱私（不蒐集資料、不提供自由輸入欄位、只用 localStorage、降級行為）
